QueryDoc came out of a straightforward frustration: asking a language model questions about a long PDF usually means either pasting huge chunks of text into a prompt or getting answers that sound confident but aren't actually grounded in the source. I wanted something that answers *from* the document, not *around* it.

The core of QueryDoc is its retrieval step. Before any question reaches the Gemini API, the system ranks the document's chunks using TF-IDF and surfaces only the sections most relevant to the query. That retrieved context becomes part of the prompt, so the model is generating an answer with the actual source material in front of it rather than relying on memorized knowledge or guesswork.

Getting deployment right took its own round of debugging — Streamlit Cloud's secrets handling needed specific configuration before the Gemini API key would resolve correctly in production, separate from how it worked locally. Once that was sorted, the app has run reliably as a live, publicly usable tool rather than just a local script.
